# 会员升级 / 成长值功能实现方案

## Context（背景）

会员系统目前有等级体系（`member_level` 表已含 `min_growth`/`max_growth`/`auto_upgrade`），但 `member` 表**没有成长值字段**，无法累计经验、无法自动升级。

本次需求：会员通过**消费/充值**获得成长值（经验），成长值达到等级阈值后**自动升级**，前端会员卡片展示成长值。

### 已确认的业务规则
- **换算**：1 元 = 1 经验（实付金额向下取整）。
- **获经验场景**：
  1. 现金/微信/支付宝**直接消费**（收银台结账，不扣会员余额）→ 获经验。
  2. **余额充值**（现金/微信/支付宝充值进余额）→ 获经验，按**实付金额**（赠送金额不计经验）。
- **不得经验场景**：余额消费（`deductBalance`）、上机扣费（余额扣）→ 不加经验。
- **自动升级**：成长值达到更高等级区间且 `auto_upgrade=1` 时升级，**只升不降**。
- 新增**成长值流水表**记录每次经验获取与升级。
- 前端：**会员卡片显示成长值**（管理后台会员详情 + 小程序个人中心）。

## 一、数据库变更

新建 `e:\StarLinkAttendant\resource\sql\MemberGrowth.sql`：

```sql
-- 会员表新增累计成长值字段
ALTER TABLE `member`
    ADD COLUMN `growth_value` INT NOT NULL DEFAULT 0 COMMENT '累计成长值（1元=1经验）' AFTER `available_points`;

-- 成长值流水表
CREATE TABLE `member_growth_log` (
    `id`              BIGINT UNSIGNED  NOT NULL AUTO_INCREMENT  COMMENT '主键',
    `member_id`       BIGINT UNSIGNED  NOT NULL                 COMMENT '会员ID → member.id',
    `growth`          INT              NOT NULL                 COMMENT '本次获得成长值（正数）',
    `growth_before`   INT              NOT NULL DEFAULT 0       COMMENT '变动前累计成长值',
    `growth_after`    INT              NOT NULL DEFAULT 0       COMMENT '变动后累计成长值',
    `biz_type`        TINYINT          NOT NULL                 COMMENT '业务类型：1-收银直接消费 2-余额充值',
    `biz_id`          BIGINT UNSIGNED  DEFAULT NULL             COMMENT '关联业务ID（订单ID/充值记录ID）',
    `level_before_id` BIGINT UNSIGNED  DEFAULT NULL             COMMENT '变动前等级ID',
    `level_after_id`  BIGINT UNSIGNED  DEFAULT NULL             COMMENT '变动后等级ID（含自动升级后）',
    `is_upgraded`     TINYINT          NOT NULL DEFAULT 0       COMMENT '本次是否触发自动升级：0-否 1-是',
    `remark`          VARCHAR(255)     DEFAULT NULL             COMMENT '备注',
    `created_at`      DATETIME(3)      NOT NULL DEFAULT CURRENT_TIMESTAMP(3)            COMMENT '创建时间',
    `updated_at`      DATETIME(3)      NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3) COMMENT '更新时间',
    `deleted_at`      DATETIME(3)      DEFAULT NULL             COMMENT '逻辑删除（NULL=未删除）',
    `version`         INT UNSIGNED     NOT NULL DEFAULT 1       COMMENT '乐观锁版本号',
    PRIMARY KEY (`id`),
    KEY `idx_member_id` (`member_id`),
    KEY `idx_biz_type` (`biz_type`),
    KEY `idx_created_at` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='会员成长值流水表';
```

## 二、后端改动（`starlink-module-member`，除注明外）

### 新增文件
1. `entity\MemberGrowthLog.java` — extends `BaseEntity`，`@TableName("member_growth_log")`，字段：`memberId(Long)`、`growth(Integer)`、`growthBefore/After(Integer)`、`bizType(Byte)`、`bizId(Long)`、`levelBeforeId/levelAfterId(Long)`、`isUpgraded(Byte)`、`remark(String)`。
2. `mapper\MemberGrowthLogMapper.java` — extends `BaseMapper<MemberGrowthLog>`。
3. `service\GrowthValueService.java` — 核心服务，见下。

### 核心：`GrowthValueService.addGrowth`

```java
@Slf4j @Service @RequiredArgsConstructor
public class GrowthValueService {
    private final MemberMapper memberMapper;
    private final MemberLevelMapper levelMapper;        // 复用 selectByGrowth
    private final MemberGrowthLogMapper growthLogMapper;

    @Transactional
    public void addGrowth(Long memberId, Integer growth, Byte bizType, Long bizId, String remark) {
        if (growth == null || growth <= 0) return;
        Member member = memberMapper.selectById(memberId);
        if (member == null) throw new BusinessException(ErrorCode.NOT_FOUND.getCode(), "会员不存在");

        int before = member.getGrowthValue() == null ? 0 : member.getGrowthValue();
        int after  = before + growth;

        // 只升不降：仅当目标等级 auto_upgrade=1 且等级高于当前时才升级
        Long oldLevelId = member.getLevelId();
        int oldOrder = (oldLevelId == null) ? 0 // 由 selectById 取 levelOrder 或 0
                : safeOrder(levelMapper.selectById(oldLevelId));
        MemberLevel target = levelMapper.selectByGrowth(after);
        Long newLevelId = oldLevelId;
        boolean upgraded = false;
        if (target != null && Byte.valueOf((byte) 1).equals(target.getAutoUpgrade())
                && oldOrder < safeOrder(target)) {
            newLevelId = target.getId(); upgraded = true;
        }

        MemberGrowthLog entry = new MemberGrowthLog();
        entry.setMemberId(memberId); entry.setGrowth(growth);
        entry.setGrowthBefore(before); entry.setGrowthAfter(after);
        entry.setBizType(bizType); entry.setBizId(bizId); entry.setRemark(remark);
        entry.setLevelBeforeId(oldLevelId); entry.setLevelAfterId(newLevelId);
        entry.setIsUpgraded(upgraded ? (byte) 1 : (byte) 0);
        growthLogMapper.insert(entry);

        member.setGrowthValue(after);
        if (upgraded) member.setLevelId(newLevelId);
        memberMapper.updateById(member);   // 乐观锁防并发覆盖
        log.info(upgraded ? "会员自动升级: id={}, level {}->{}" : "会员成长值增加: id={}, after={}",
                memberId, oldLevelId, newLevelId); // 按需精简
    }
    private int safeOrder(MemberLevel l) {
        return l == null || l.getLevelOrder() == null ? 0 : l.getLevelOrder();
    }
}
```

## 三、接入点

### 1. 充值 `RechargeService.recharge`（member 模块）
`memberMapper.updateById(member)` 后、返回前加入：
```java
growthValueService.addGrowth(request.getMemberId(),
        request.getAmount().setScale(0, RoundingMode.DOWN).intValue(),   // 实付，不含赠送
        (byte) CommonConstants.GROWTH_BIZ_RECHARGE, recharge.getId(),
        "余额充值获得成长值（实付" + request.getAmount() + "元）");
```
注入 `private final GrowthValueService growthValueService;`。

### 2. 收银直接消费 `OrderServiceImpl.payOrder`（cashier 模块）
`orderMapper.updateById(order)` 后、`updateShiftOnTransaction` 前加入：
```java
if (order.getMemberId() != null && request.getPaymentMethod() != null
        && request.getPaymentMethod() != CommonConstants.PAY_METHOD_BALANCE) {
    growthValueService.addGrowth(order.getMemberId(),
            order.getPayableAmount().setScale(0, RoundingMode.DOWN).intValue(),
            (byte) CommonConstants.GROWTH_BIZ_CONSUME, orderId, "收银消费获得成长值");
}
```
注入 `private final GrowthValueService growthValueService;`（cashier pom 已依赖 member 模块）。

> 余额支付（method=4，走 `deductBalance`）与上机扣费天然不进入本分支，满足"余额消费不加经验"。

## 五、一致性考量
- 成长值累加、流水、等级更新在同一 `@Transactional`（REQUIRED）内原子提交。
- 并发安全：`memberMapper.updateById` 依赖 `BaseEntity.version` 乐观锁，防止并发累加覆盖丢失。
- 防重复：`payOrder` 已有幂等键 + 已支付状态机拦截；`recharge` 每次新单号新记录。

## 六、验证方案（端到端）
1. **充值升级**：新会员现金充值 1200 → `growth_value=1200`、`level_id` 升银卡、流水 `biz_type=2`、`is_upgraded=1`。
2. **余额消费不加经验**：余额支付一笔订单 → 余额扣减成功但 `growth_value` 不变、无新流水。
3. **直接消费加经验**：现金/微信/支付宝支付订单 → `growth_value` 增 = 应付向下取整、`biz_type=1`。
4. **升级后折扣生效**：升金卡后充值 → 赠送比例取新等级 `recharge_bonus_rate`。
5. **只升不降 / auto_upgrade=0**：把某等级 `auto_upgrade` 置 0 → 充值越过该区间 `level_id` 不变但成长值/流水正常。
6. **前端**：小程序个人中心、管理后台会员详情显示成长值。
7. **并发**：两笔并发充值 → 最终 `growth_value` 为两笔之和（乐观锁不丢）。
