# 小程序热门商品对接真实后端

## Context（背景）

小程序首页"热门商品"目前由 mock 提供：`GET /api/member/products/hot` 命中 [mock/routes.ts](file:///e:/StarLinkAttendant/resource/xiaochengxu/src/mock/routes.ts#L440-L447) 返回 `seed.seedProducts.filter(p => p.hot)` 的写死数据。这些假数据与 Web 管理端/收银端使用的真实 `product` 表商品不一致（`hot:true` 与真实销量也对不上，如"农夫山泉"销量2210 未标 hot，而"双人开黑套餐"销量320 标了 hot）。

用户明确要求：**小程序"热门商品"要对齐 Web 端真实商品**，且**按销量自动取 Top N**。讨论后确认：热门商品列表对接真实后端 `product` 表数据按销量排行；**点击真实商品时给出友好提示，不跳转详情**（详情/下单仍走 mock，真实商品 id 在 mock 目录查不到）。

目标：让首页热门商品在 `VITE_USE_MOCK=true`（混合模式）下也穿透 mock 直连真实后端，返回真实 `product` 表中销量 Top N 的上架商品。

## 实现方案

### 一、后端：新增热门商品接口

**1. 新增响应 DTO** — `starlink-module-product` 的 `dto/resp` 下新建 `HotProductResponse.java`，字段对齐小程序 `Product` 首页所需（同时补齐可映射字段）：

* `id`(=product.id)、`name`(=product\_name)、`categoryId`(=category\_id)、`type`(=product\_type 映射 1→1/2→2/其余→2 虚拟)

* `price`(=retail\_price)、`memberPrice`(=member\_price)、`unit`(=unit)、`sales`(=SUM(oi.quantity))、`cover`(=image\_url)、`status`(=is\_active)

**2. 新增查询** — 在 [ProductMapper.java](file:///e:/StarLinkAttendant/BackEnd/Backend/starlink-module-product/src/main/java/com/starlink/product/mapper/ProductMapper.java) 用 `@Select` 直接对共享数据源跑 SQL（无需跨模块 Java 依赖，复用报表模块 [ReportMapper.selectProductRanking](file:///e:/StarLinkAttendant/BackEnd/Backend/starlink-module-report/src/main/java/com/starlink/report/mapper/ReportMapper.java#L112-L118) 的同款 JOIN 思路）：

```sql
SELECT p.id, p.product_name, p.category_id, p.product_type, p.unit,
       p.retail_price, p.member_price, p.image_url, p.is_active,
       COALESCE(SUM(oi.quantity),0) AS sales
FROM product p
LEFT JOIN order_item oi ON oi.product_id = p.id
  AND oi.item_type = 1 AND oi.deleted_at IS NULL
LEFT JOIN orders o ON o.id = oi.order_id AND o.deleted_at IS NULL AND o.paid_at IS NOT NULL
WHERE p.deleted_at IS NULL AND p.is_active = 1
GROUP BY p.id
ORDER BY sales DESC, p.id ASC
LIMIT #{limit}
```

* `LEFT JOIN` 保证销量为 0 的上架商品也能进入候选，避免商品少时列表为空

* **不要参数拼接**，用 `#{limit}` 预编译占位符

**3. Service 与 Controller** — 在 [ProductService.java](file:///e:/StarLinkAttendant/BackEnd/Backend/starlink-module-product/src/main/java/com/starlink/product/service/ProductService.java) + impl 加 `listHotProducts(int limit)`；新增 `MemberProductController`（`@RestController @RequestMapping("/api/member/products")`），方法 `@GetMapping("/hot")` 接收 `@RequestParam(defaultValue="6") int limit`，返回 `Result<List<HotProductResponse>>`（limit 做 `>=1 && <=50` 收敛）。

> 该模块只依赖 `starlink-common`，`Result` 已在 [ProductController.java](file:///e:/StarLinkAttendant/BackEnd/Backend/starlink-module-product/src/main/java/com/starlink/product/controller/ProductController.java) 使用，无新增依赖。

### 二、后端：安全放行

[SecurityConfig.java](file:///e:/StarLinkAttendant/BackEnd/Backend/starlink-system/src/main/java/com/starlink/system/config/SecurityConfig.java#L55-L57) 的会员自助白名单区（第 57 行之后、第 78/79 行 `"/api/member/**"` 角色规则**之前**）新增：

```java
.requestMatchers(HttpMethod.GET, "/api/member/products/hot").permitAll()
```

首页合家欢在未登录时也需展示热门商品，故公开即可。规则自上而下首个匹配生效，必须放在 `"/api/member/**"` 之前。

### 三、前端：穿透 mock + 点击提示

**1.** **[request.ts](file:///e:/StarLinkAttendant/resource/xiaochengxu/src/api/request.ts#L38-L52)** — `isMemberEndpoint()` 追加一条：`u === '/api/member/products/hot'`，使其在 `USE_MOCK=true` 时也直连真实后端（BASE\_URL/代理已支持 `/api/member`，登录/充值已穿透验证可行）。

**2.** **[api/product.ts](file:///e:/StarLinkAttendant/resource/xiaochengxu/src/api/product.ts#L26-L29)** — `getHotProducts` 保持路径不变，响应后做字段映射：后端 `name/cover/sales/memberPrice/price` → 前端 `Product`，缺失字段补默认（`stock:0`、`spec`/`tags` 省略、`hot:false`）。保持返回 `Product[]`。

**3.** **[pages/index/index.vue](file:///e:/StarLinkAttendant/resource/xiaochengxu/src/pages/index/index.vue#L191-L193)** — `onProductTap` 改为点击提示，不跳详情：

```ts
function onProductTap(_p: Product): void {
  toast('该商品暂未上架自助点餐')
}
```

真实商品 id 不在 mock 点单目录，避免跳到 `detail?id=<真实id>` 后报"商品不存在"；`onProductTap` 仅热门商品卡片使用，无其他影响。

## 验证

1. **后端**：启动 Spring Boot（8080），`curl "http://localhost:8080/api/member/products/hot?limit=4"`，无需 token（公开），应返回按销量倒序的真实 `product` 上架商品，字段含 `id/name/price/memberPrice/sales/cover`。
2. **前端混合模式**（`VITE_USE_MOCK=true`）：首页热门商品从真实后端加载，与后台商品表销量 Top N 对上，非 mock 假数据。控制台不出现 issue。
3. **点击**：点任一热门商品弹 toast"该商品暂未上架自助点餐"，不透传 id 到详情、不报"商品不存在"。
4. **回退场景**：后端未启动时首页热门商品走真实接口失败→该区块显示"暂无推荐商品"而非假数据（符合"对接真实"的语义，已知可接受）。

## 已知边界

* 首页热门商品仅列表对齐；详情/自助点餐/下单仍为 mock，故点击热门商品只做提示、不深链。

* 商品售价等以 `product` 表为准，`memberPrice` 为空的商品首页显示 `price`（现有 `memberPrice ?? price` 逻辑天然兼容）。
