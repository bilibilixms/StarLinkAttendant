# 小程序对接后端会员接口

## Context

新增的小程序（`resource/xiaochengxu`）当前所有 API 调用都基于一个设想的前缀 `/api/applet/**`，但后端并没有该前缀的接口。后端实际只为小程序会员准备了两个公开接口 `POST /api/member/login` 和 `POST /api/member/register`（在 [SecurityConfig.java](file:///e:/StarLinkAttendant/BackEnd/Backend/starlink-system/src/main/java/com/starlink/system/config/SecurityConfig.java#L37) 中 `permitAll`），其他会员相关业务接口（充值、积分记录、充值记录）也都挂载在 `/api/member/**` 下，但设计上是给员工端管理后台调用的（需要会员 id 参数）。

小程序是只提供给"会员用户"使用的，登录方式只能是手机号+密码（对齐后端 [MemberLoginRequest](file:///e:/StarLinkAttendant/BackEnd/Backend/starlink-module-member/src/main/java/com/starlink/member/dto/req/MemberLoginRequest.java)），不能保留微信 code 登录、Demo 登录、短信验证码登录等后端不支持的入口。

本次修改的目标：
1. 把会员相关接口（登录、充值下单、充值记录、积分记录）对接到后端真实的 `/api/member/**` 接口
2. 删除后端不存在的接口调用（profile、summary、sign-in、verify、bind、logout 等）
3. 简化登录页只保留手机号+密码登录
4. 订单、会话、商品、社区、游戏等业务保留走 mock 层（后端没有专门给小程序的接口）

不在本次修改范围：
- 不修改后端代码
- 不对接订单/会话/商品等业务接口（这些后端是给员工端管理后台用的）
- 不调整后端 `MemberLoginResponse` 的字段（小程序端用默认值填充未返回的字段）

## 决策与约束

- **API_PREFIX** 从 `/api/applet` 改为 `/api/member`（[src/config/index.ts](file:///e:/StarLinkAttendant/resource/xiaochengxu/src/config/index.ts#L6)）
- **登录方式**：只保留手机号+密码登录；删除微信一键登录、Demo 登录、手机号绑定三条入口
- **会员 id 来源**：登录响应 `MemberLoginResponse.id` 缓存到本地 `Member.id`，后续调用充值记录、积分记录接口时使用该 id
- **字段映射**：`MemberLoginResponse` 只有 7 个字段（token, id, memberNo, realName, phone, levelName, totalPoints, balance），小程序 `Member` 类型的其他字段（nickName, avatar, availablePoints, totalRecharge, totalConsumption, totalOnlineHours, status, verified 等）在 `applyLogin` 中用默认值填充（空串/0/正常状态 1）
- **会员资料相关接口**：删除 `getProfile`、`updateProfile`、`getMemberSummary`、`signIn`、`verifyIdentity`（后端均无此接口）
- **充值套餐、积分商品、积分兑换**：删除对应接口（后端无此接口），相关页面如果调用会报"接口未实现"，由后续后端开发时补回
- **mock 路由清理**：删除 auth、member/profile、member/summary、member/sign-in、member/verify、recharge 相关 mock 路由；保留 orders、session、products、reservations、coupons、community、game 等业务 mock 路由
- **USE_MOCK 不变**：仍由 `VITE_USE_MOCK` 控制，但语义改为"非会员业务接口走 mock"（订单、会话、商品等）
- **不修改后端任何文件**

## 已知风险

1. **mock 路由前缀变更**：`API_PREFIX` 改为 `/api/member` 后，所有 mock 路由路径都需重新审视，避免与真实后端接口路径冲突。建议保留的 mock 路由路径全部改为硬编码绝对路径（如 `/api/cashier/orders`），不依赖 `API_PREFIX`。
2. **字段映射不完整**：后端 `MemberLoginResponse` 字段少，小程序 `Member` 类型字段多，未返回字段用默认值填充，UI 上可能显示不完整（如头像、昵称为空）。后续后端补 `getProfile` 接口时再完善。
3. **充值记录/积分记录的 id 来源**：依赖登录响应缓存的 `member.id`，如果用户清缓存后未登录直接访问会拿不到 id。需在调用前检查 `user.member?.id`，缺失时跳转登录页。
4. **充值套餐、积分商品页面**：删除对应接口后，相关页面会报"接口未实现"。建议在这些页面加占位提示"功能开发中"，避免白屏。
5. **`MemberSummary` 类型被首页/我的页使用**：删除 `getMemberSummary` 后这些页面需重构数据来源（先用本地 `user.member` 兜底），可能引发较多页面改动。实施时需逐个检查 `grep "getMemberSummary"` 的调用方。
